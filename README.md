# Сервис управления производственными заданиями

## Краткое описание
Сервис управления производственными задачами (Job): доменная логика + REST API поверх неё + хранение в PostgreSQL.

Стек: Python, FastAPI, SqlAlchemy, Pydantic, PostgreSQL
> Могла пропустить какие-то детали, уникальные для питона (мало опыта с ним + пришлось быстро учиться)

## Локальный запуск (без Docker)
Следуйте этим шагам, чтобы развернуть проект на вашей машине.

### 1. Клонирование репозитория
```bash
git clone <ссылка_на_ваш_репозиторий>
cd <имя_папки_проекта>
```
### 2. Создание виртуального окружения
Рекомендуется использовать виртуальное окружение для изоляции зависимостей.
Для macOS / Linux:
```bash
python3 -m venv venv
source venv/bin/activate
```
Для Windows:
```cmd
python -m venv venv
venv\Scripts\activate
```
### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```
(Если вы планируете запускать тесты, используйте pip install -r requirements-dev.txt)

### 4. Настройка конфигурации
Файл с реальными настройками (config.py) исключен из репозитория в целях безопасности.
Для запуска создайте его в папке app/core/config.py и добавьте переменную подключения:
```
# Пример содержимого config.py
DATABASE_URL = "postgresql+asyncpg://user:password@localhost:5432/your_db_name"
```
Убедитесь, что параметр DATABASE_URL указывает на вашу локальную базу данных PostgreSQL.

### 5. Запуск приложения
Запустить приложение можно либо с помощью команды
`uvicorn app.main:app --reload`,
либо запустив app/main.

После запуска приложение будет доступно по адресу:
Swagger UI (Документация API): http://localhost:8000/docs

## Детали проекта
### Структура проекта
- app/main.py — Точка входа в приложение и роуты
- app/domain — Модели предметной области
- app/storage — Репозитории (Две реализации: InMemoryJobRepository и SqlAlchemyJobRepository
- app/service — JobService для взаимодействия api и репозиториев
- app/api — Схемы валидации данных (Pydantic) 
- app/config.py — Настройки приложения (игнорируется git)

### Ошибки (Exceptions)
Для ошибок реализовала наследование. 
- JobServiceError - базовый класс
- JobNotFoundError - работа не найдена (код 404)
- InvalidStatusTransitionError - невозможный переход статусов (код 409)
- InvalidJobDataError - ошибка в данных (выбрала 422 код, а не 400, т.к. он предполагает логическую ошибку,  а не синтаксическую. В плане, что данные физически можно использовать, но в рамках предметной области - нельзя)
